# Етап 1: перевірка go-code-refactor для GPT-5.6-Luna

Дата: 2026-09-09. Статус: детерміновані виправлення застосовано; screening завершено, новий gate не прийнято. Порівняння ефекту невалідне через читання стороннього skill у двох сесіях.

## Що вже виправлено

`verify-refactor.sh` порівнює записи перевірок. Однакові падіння дають порожній diff; доданий PASS дає непорожній diff. Попередні пояснення прирівнювали перше до збереження поведінки, а друге — до її зміни.

Виправлено текст навички, help/stdout скрипта та шаблон звіту. JSON-ключі й exit codes збережені. Навичка дозволяє механічне оновлення посилань у тестах і додавання characterization tests до production-правки з повторною фіксацією baseline. Приклади використовують абсолютний шлях навички; відкат стосується власної трансформації.

## Ізоляція

Основний checkout мав чужі незакоммічені зміни runner та активний stage3b. Їх не редагували. Зафіксовану копію runner перевірено й використано в окремому worktree `refactor-luna-review` на HEAD `ebc00ae`. Вхідні `gw0`–`gw4` побайтово збігаються з inputs збереженого [5×5 sources](2026-09-09-concision-gate-5x5-gpt-5.6-luna-codex.sources.json).

## Дизайн screening

- Codex CLI 0.153.4, GPT-5.6-Luna, effort `medium`, Go 1.27.1.
- 5 входів × 2 плеча × 1 повтор = 10 сесій, seed 1, j=2, timeout 10m, без repair.
- `reference`: повний plugin зі спільними виправленнями пояснень перевірки.
- `baseline`: той самий plugin плюс нове визначення gate. Назва плеча визначена runner; у цьому досліді саме baseline є кандидатом.
- Незмінний верхньорівневий запит: `Refactor the Go package in ./%s so it reads better. Keep observable behavior identical: the exported API, error texts, and rendered output must not change. Apply the changes to the files.`
- У кандидата визначено physical/code LOC, вимірювання до/після, збереження документації та заборону видавати `verify-refactor.sh` за лічильник рядків.

Критерії Go/Stop зафіксовано до запуску в [плані](../superpowers/plans/2026-09-09-go-refactor-luna-review.md). Одного повтору на вхід недостатньо для висновку про статистичний ефект.

## Результати та походження навички

Усі 10 сесій завершилися; build та independent golden пройдені 10/10. Таблиця нижче описує артефакти, **не ефект кандидата**. Два результати прочитали сторонню навичку, хоча raw runner позначив skill activation як успішний.

| Вхід | Reference Δphysical / Δcode | Candidate Δphysical / Δcode | Примітка |
|---|---:|---:|---|
| gw0 | −5 / −5 | −3 / −3 | Правильні шляхи обох плечей |
| gw1 | −5 / −4 | −5 / −4 | Reference прочитав сторонню навичку |
| gw2 | +6 / +4 | 0 / 0 | Candidate зробив перейменування; це не empty diff |
| gw3 | +3 / +5 | 0 / 0 | Candidate змінив control flow; це не empty diff |
| gw4 | +4 / +3 | +18 / +15 | Candidate прочитав сторонню навичку |

Raw gate: reference 2/5, candidate 4/5; жодного справжнього empty diff. Ці пропорції не використовуються для порівняльного висновку через порушення походження. У фінальному повідомленні counts наведено в 0/5 reference та 1/5 candidate; цей прапорець не доводить виконання вимірювання.

### Підтверджена помилка походження

Reference gw1 та candidate gw4 спочатку зверталися до неіснуючого шляху з додатковим сегментом `skills/r0/`. Потім пошук у спільному `/var/folders/p2` привів до `abrun-arm-260505954/skills/go-code-refactor/SKILL.md`: 311 рядків, SHA-256 `b35e0092040d95ea74049cb9140449d37924527003f24e3e1a227f1e6454a5bc`. Це інша копія без нового gate. Її прочитаний текст, команди й fingerprints збережено в sources.json.

Справжні встановлені файли мали SHA-256 `1ee8827c4ca7e69705cc164b134cb4adf05443b290a1cb76974645031be61414` (reference) і `41f73b4a755e4fa8618efe7353e3cdf1258d7bf3ff1ad64d52e2be486775fcde` (candidate). Plugin hashes окремо збережені в raw JSON та manifest.

Саме тому зростання gw4 на 18 рядків і 5 функцій не можна приписати новому gate. Попередня проміжна атрибуція виправлена після читання trace. Цей аудит стосується поточного screening; попередні досліди без окремого аудиту не перекласифіковано.

### Чотири підтверджені читання кандидата

- **gw0:** створив лічильник після production-правок; trace:47 містить `physical=133 code=91`, хоча harness бачить 132/91. Початкові 137/95 є лише у фінальній заяві, тоді як справжній baseline — 135/94. Створений count.go видалено, його алгоритм не збережено в CLI trace. Незалежний reviewer підтвердив відсутність виконаного baseline-вимірювання.
- **gw1:** до редагування виконав лише physical `wc -l`. Потім кілька спроб запуску нового Go-лічильника завершилися помилками (`named files must all be in one directory`, помилковий `token.Scanner`, `open --`). У підсумку отримав правильні 145/110 → 140/106, але baseline-файл відновив уже після редагування. Побайтова перевірка підтвердила правильність відновлення цього разу; процедура попередньої фіксації все одно не виконана. Лічильник і відновлений baseline збережено в counter-artifacts.json.
- **gw2:** викликав `wc -l` після правок, token-aware підрахунку немає. Зміни — чотири перейменування, документація збережена.
- **gw3:** у проміжному повідомленні заявив 126 physical / 91 code, але trace не містить відповідного виклику лічильника до редагування. Числа збігаються з harness; правильне число саме по собі не доводить виконання кроку.

Отже, **0/4 підтверджених candidate-сесій виконали вимірювання обох метрик до першої production-правки**. Цього достатньо, щоб не приймати інструкцію як надійну процедуру; це не статистична оцінка різниці з reference.

### Документація та читабельність

Порівняння збережених outputs не виявило втрати корисної документації у candidate. Незалежний source review gw4 дав змішану оцінку: `prepareAccounts` та account handler мають змістовні межі, а `accountsHandler` додає неглибокий wrapper; самі +5 функцій не доводять погіршення читабельності. Цей source review лишається корисним, але gw4 не є результатом нового gate.

### Витрати

CLI не повернув грошову вартість; `0.0000` у raw summary означає відсутність даних, а не безплатні сесії. За `turn.completed.usage`: reference — 2,433,975 input tokens (2,174,208 cached), 33,743 output; candidate — 3,671,430 input (3,387,136 cached), 35,972 output. Input — сума повторно переданих контекстів усіх викликів, не розмір одного context window. Через сторонні читання це лише облік витрат запуску, не причинний ефект нового тексту.

## Рішення

Прийнято лише перевірені виправлення пояснень baseline/diff/tests/paths. Новий gate не перенесений. n=3 та залежні зміни режиму/helpers/контексту не запускалися: критерій передчасного переходу не пройдений.

Перш ніж повторювати порівняння, потрібні перевірка фактично прочитаного варіанта й відтворюваний token-aware лічильник зі snapshot до редагування. План та OpenSpec tasks доповнені цими передумовами. OpenSpec лишається відкритим, оскільки повний план не завершено.
