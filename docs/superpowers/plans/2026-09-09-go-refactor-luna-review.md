## Виконані передумови повторного screening

Обидві передумови реалізовані та перевірені детерміновано в ізольованому
worktree; у checkout нічого не переносилося. Повний опис і таблиці перевірок —
[звіт передумов](../../evidence/2026-09-09-refactor-luna-review.preconditions.md).

- Походження: `auditSkillReads` класифікує кожне читання `SKILL.md` за коренем
  skills свого плеча — assigned, foreign (зі SHA-256 прочитаних байтів) або
  unresolved. Foreign дає окремий label `SKL`, виключає run із середніх і
  окремий рядок у зведенні; вирішує вміст, а не шлях, тому побайтово однакова
  копія не вважається іншим варіантом. `codexEnv` додатково віддає кожному
  плечу власний `TMPDIR`, бо обидва сторонні читання починалися з пошуку в
  спільному системному temp.
- Лічильник: режими `loc-baseline`/`loc-diff` у `verify-refactor.sh` v1.1.0.
  `loc-baseline` записує обидва числа та SHA-256 кожного файла до редагування,
  `loc-diff` перераховує; exit code — вердикт. Конвенція збігається з `analyze`
  у harness і перевірена проти нього, а не лише проти власних очікувань.

Checkpoint-прогін `gw0` на двох плечах виявив дефект самої перевірки: корінь
плеча — `/var/folders/...`, а shell сесії повідомляє той самий файл як
`/private/var/folders/...`, тому всі правильні читання класифікувалися як
сторонні. Виправлено нормалізацією symlinks; випадок закритий тестом. Це
приклад того, чому передумову перевіряють на реальному прогоні, а не лише
юніт-тестами.

Кандидат оновлено під наявний інструмент: gate називає обидві команди та
вердикт за exit code замість «use a tool», а шаблон звіту кандидата вимагає
надрукований `loc-diff` — це закриває P3-зауваження попереднього рев'ю. Обидва
