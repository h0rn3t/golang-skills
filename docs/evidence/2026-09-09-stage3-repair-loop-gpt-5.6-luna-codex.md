# Этап 3 — автоматический repair loop, GPT-5.6-Luna (medium) на Codex

2026-09-09. Пять фиксированных gateway-входов, три повтора, два плеча: 15
сессий prose-only и 15 с одним автоматическим repair-turn-ом. **Четыре из пяти
Go-критериев выполнены с большим отрывом. Пятый — нет: 2 из 15 прогонов взяли
гейт, удалив документацию. Расширять до `n=5` нельзя, пока эта дыра открыта.**

- Line gate: **8/15 prose против 15/15** с петлёй.
- Медиана Δlines: **+0 против −3**; среднее **+1.00 против −2.80**.
- Максимум: **+17 против +0** — после петли ни один прогон не вырос.
- Golden 15/15 на обоих плечах; петля починила регрессию `nil → null`, ту же,
  что прогон 5×5 отгрузил как behavior failure.
- Эффект −3.80 строки, within-input randomization **p = 0.01572**.
- Ни одного чистого откката: все 15 результатов переписаны.

## Дизайн

Плечи различаются **только петлёй**. Один плагин (SHA-256 совпадает), один
prompt (штатный `refactorPrompt`), одни входы, один seed. Прошедший этап 1
кандидат-prompt намеренно не использован: его эффект не установлен, и смешивать
две переменные в одном прогоне значило бы не измерить ни одной.

Петля (`abrun -repair`):

```text
сессия → measure production LOC → probe golden на выбрасываемой копии
       → если гейт или golden упали: вернуть числа и текст ассерта
       → один repair-turn → measure и probe заново
```

Второй турн выдаётся только промахнувшимся: в 9 из 15 прогонов гейт и golden
были зелёными сразу, и петля не тратила сессию.

Две вещи делают это экспериментом, а не утечкой, и обе закреплены тестами.
Probe идёт на копии всего модуля, поэтому golden никогда не попадает в дерево,
которое читает модель, а её собственные тесты остаются на месте
(`TestProbeGoldenLeavesTreeUntouched`). Падение доходит как текст ассерта с
вырезанными file:line, поэтому модель узнаёт, *что* сломалось, а не в каком
файле лежит тест (`TestRepairFeedback`).

Feedback называет конвенцию подсчёта — прямое применение находки этапа 2, где
сессия прочитала тот же файл как 101 строку там, где харнесс читал 138, и
объявила гейт взятым. Пример того, что реально получила модель:

```text
Package under review: ./gw0

Starting production LOC: 135
Current production LOC: 129
Gate: PASS on line count.
LOC counts physical lines in the package's non-test *.go files, blank lines and comments included.

Independent contract failure:
--- FAIL: TestEmptyListIsJSONArray/nil (0.00s)
GET /accounts = 200 "null", want 200 []

Repair the implementation or restore the starting version.
Done when LOC <= 135 and the contract test passes.
```

Имя теста в тексте ассерта до модели доходит; путь к файлу — нет. Это
осознанно: сообщить, что сломалось, нельзя, не назвав проверку, а сыграть
против такой информации можно только починив само поведение.

## Запуск

- Runner: Codex CLI 0.153.4; model `gpt-5.6-luna`; effort `medium`.
- 5 входов × 3 повтора × 2 плеча = 30 сессий; seed 1; `j=4`; timeout 10 минут;
  `-keep`. Плечо с петлёй потратило 6 дополнительных турнов, итого 36 сессий
  модели.
- Plugin SHA-256 обоих плеч:
  `5509f19786639774c1bc6e6bc822d5f8fd7ae56efab7836976fbff63a6b89148`.
- Ни одного `leaked`, `harness_failure` или `behavior_failure` в финальных
  замерах обоих плеч.
- Первый запуск упал на разборе флагов, не потратив ни одной сессии: `zsh` не
  разбивает незакавыченную переменную на слова, и вся строка флагов ушла одним
  аргументом. Перезапущено с флагами в явном виде.

## Результаты

| Вход | Prose Δlines (3 повтора) | С петлёй Δlines (3 повтора) |
|---|---|---|
| `gw0` | −5, −5, −5 | −6, −7, −5 |
| `gw1` | **+17**, −5, −5 | −3, +0, −5 |
| `gw2` | +0, +4, +3 | −1, +0, +0 |
| `gw3` | **+11**, +4, +0 | +0, −3, −1 |
| `gw4` | +3, −4, +2 | −6, +0, −5 |
| **Гейт** | **8/15** | **15/15** |
| **Медиана** | **+0.0** | **−3.0** |
| **Максимум** | **+17** | **+0** |

Эффект −3.80 строки; exact randomization со сменой labels только внутри каждого
фиксированного входа, 200 000 перестановок: **two-sided p = 0.01572**.

Петля сработала в 6 прогонах и во всех шести вывела результат в зелёное по
гейту и golden:

| Прогон | До петли | После | Golden |
|---|---:|---:|---|
| `gw0 #0` | −6 | −6 | **False → True** |
| `gw1 #1` | +2 | +0 | True → True |
| `gw2 #0` | +10 | −1 | True → True |
| `gw2 #1` | +8 | +0 | True → True |
| `gw3 #2` | +1 | −1 | True → True |
| `gw4 #1` | +5 | +0 | True → True |

### Петля поймала не только рост

`gw0 #0` — единственный прогон, где петлю запустил не гейт, а независимая
проверка: первый турн сократил код на 6 строк и сломал wire shape, вернув
`null` вместо `[]` для nil-списка. Это **та же регрессия**, которую прогон 5×5
отгрузил как подтверждённую behavior failure и о которой финальное сообщение
модели тогда ошибочно заявило сохранение nil-поведения. Здесь петля вернула
модели текст ассерта, и второй турн починил контракт, сохранив −6 строк.

### Разброс внутри входа велик

`gw1` на prose-плече дал −5, −5 и **+17** при одинаковых prompt, плагине и
seed. Это ретроспективно обесценивает точность этапов 1 и 2, где было `n=1` на
вход: −1.20 строки этапа 1 находится глубоко внутри собственного шума одной
фикстуры.

## Пятый критерий не выполнен

Ручной review нашёл не code golf, а хуже — **платёж документацией за код**.

`gw2 #0` и `gw2 #1` (оба сработали через петлю) удалили из doc-комментария
`NewServer` абзац, объясняющий, что сервер стоит на открытом интернете без
прокси, что клиенты анонимны, а часть трафика приходит выяснять, сколько
соединений процесс способен удержать. Это **обоснование таймаутов**. Взамен
оба добавили новые функции-хелперы.

Замер по всем 30 прогонам:

| Плечо | Δфизических | Δкомментариев | Δкода |
|---|---:|---:|---:|
| prose | +1.00 | +0.00 | +0.40 |
| с петлёй | **−2.80** | **−1.07** | **−1.73** |

Системным это не является: 13 из 15 прогонов сократили именно код, и основная
часть эффекта плеча (−1.73 из −2.80) — код, а не комментарии. Но два прогона
из пятнадцати — оба на `gw2`, оба после петли — срезали 8 строк комментария,
добавив 6 строк кода: Δфизических −1 и +0, гейт PASS, golden зелёный.

Причина — **в моём собственном определении LOC**. Гейт считает физические
строки, включая комментарии, поэтому удаление документации легально
оплачивает добавление кода. Это ровно Stop-критерий этапа 3: «сокращает код
ценой понятности/полезной локальности».

Та же дыра открыта и у пользователей: гейт, отгруженный в main, требует «no
more production lines», не исключая комментарии.

## Go-критерии

| Критерий | Результат |
|---|---|
| Golden 15/15 | ✓ 15/15 |
| `Δlines ≤ 0` минимум в 14/15 | ✓ **15/15** |
| Медиана не выше нуля | ✓ **−3.0** |
| После repair ни одного результата больше +5 | ✓ максимум **+0** |
| Ручной review не находит code golf | ✗ 2/15 взяли гейт, удалив документацию |

## Решение

**Не расширять до `n=5`.** План разрешает Expand только после выполнения всех
критериев, а пятый не выполнен. Расширение сейчас купило бы точность оценки
эффекта, который частично достигается нежелательным способом.

Петля при этом работает и работает сильно: гейт 8/15 → 15/15, медиана +0 → −3,
максимум +17 → +0, шесть промахов из шести вытянуты в зелёное, включая одну
реальную регрессию контракта, и ни одного откката. Отказываться от неё
результат не даёт оснований — он даёт одно конкретное исправление.

Следующий шаг — не этап 4 и не `n=5`, а закрыть дыру и перепроверить те же 30
сессий:

1. Считать в гейте строки кода отдельно от комментариев и запрещать рост кода,
   компенсированный удалением документации. Поле для этого — новое, `Δcode`;
   `Δlines` остаётся как есть, чтобы не рвать сравнимость с прошлыми отчётами.
2. То же ограничение назвать в тексте feedback-а: сокращение не оплачивается
   документацией.
3. Затем перезапустить этап 3 и только после чистого пятого критерия — Expand.

Правки скилла из этого прогона не следует: петля живёт в харнессе, а не в
`SKILL.md`. Но одна вещь для скилла из него следует **как исправление уже
отгруженного текста**: гейт в `go-code-refactor` должен исключать комментарии
из счёта, иначе он поощряет то же самое у пользователей. Это правка
формулировки скилла и по правилу репозитория идёт через вариант и измерение.
