# Sonnet 5: сокращение go-http

> Решение 2026-09-09 после отчёта: по указанию пользователя выбран компактный
> inline-вариант, дополненный правилами для HEAD, пустого массива и строгого
> лимита ответа. В `abrun` и quality-режиме `evalrun` исправлено расположение
> плагина. Это новая комбинация; таблицы ниже описывают только исходные
> эксперименты и не доказывают её экономичность. Исторические patches сохранены.

> Проверка выбранной комбинации: Go-тесты репозитория и проверка примера
> строгого лимита проходят. В двух новых Sonnet-сессиях сборка и проверки
> nil/empty/полностью отфильтрованного списка прошли, но HEAD остался 200
> вместо 405: новый golden дал 0/2. Это проверка границ, а не доказательство
> улучшения модели. Сохранены [отчёт](2026-09-09-sonnet-http-selected-smoke.json),
> [исходники](2026-09-09-sonnet-http-selected-smoke.sources.json) и
> [журналы](2026-09-09-sonnet-http-selected-smoke.traces.tar.gz).

2026-09-08 UTC; запуск завершён ночью 2026-09-09 по Киеву.

**Устойчивой экономии не установлено. Оба варианта оставлены
экспериментальными.** Проверены сокращение с выносом клиентов и сокращение
с сохранением клиентских правил внутри. В ходе проверки обнаружено, что
штатное расположение плагина в `abrun` делает его справочники недоступными
для `Read` при `--restricted`. После исправления расположения в отдельном
экспериментальном драйвере проведена новая серия; результаты не объединяются.

## Варианты

Общая база — `74ca0fa`, тот же checkout, что в предыдущем
[эксперименте маршрутизации](2026-09-08-sonnet-routing-execution-pocock.md).
Файлов второго раунда из пересланного пользователем отчёта в checkout нет.
Это проверка сокращения доступного текста, а не сравнение с тем вторым раундом.

| Вариант | Слов в SKILL.md | Изменение |
|---|---:|---|
| `baseline` | 1201 | Исходный текст |
| `split` | 797, −34% | Клиенты перенесены в `references/CLIENTS.md` (101 слово); убрана повторная таблица, сокращены пояснения и Related Skills |
| `inline` | 891, −26% | Клиентские правила сохранены внутри; убраны повторы и сокращены пояснения |

В обоих вариантах сохранены исходное описание скилла, пример декодирования
и таблица HTTP-статусов. `split` уточняет условие чтения `WEB-SERVER.md` до
startup/shutdown; `inline` сохраняет исходное условие. `inline` также
восстанавливает явную оговорку об использовании уже принятого в проекте
фреймворка. Это пакеты текстовых изменений, не чистый эксперимент с числом
слов. В частности, в обоих вариантах Validation стал отдельным разделом с
императивом `Run` вместо исходной цитаты.

Изменения остальных скиллов, включая проверенный ранее шаг 3 `go-code`,
в эти варианты не включены.

### Ограничение, обнаруженное в журналах

В `abrun` плагин находится в `abrun-arm-*`, а проект — в соседнем
`abrun-work-*`. `Skill` загружает основной текст, но прямое чтение справочника
за пределами рабочего каталога получает ошибку:

```text
--restricted confines the file tools to the working directory.
```

Три split-сессии пытались прочитать `WEB-SERVER.md`; все три чтения отклонены.
Одна из двух клиентских split-проб пыталась прочитать `CLIENTS.md`; это чтение
тоже отклонено. Другая не вызвала его чтение. **Успешных загрузок CLIENTS.md
в первой серии — 0/2.** В промежуточных сообщениях вызовы были преждевременно
названы чтением; итоговые данные учитывают успешные ответы инструментов.

Первая серия описывает поведение этого стенда, но не позволяет оценить
надёжность выноса при доступном справочнике. Это ограничение не объясняет
пропуски `Skill` для дополнительных owner-ов: вызовы `Skill` работают.

## Повтор с доступными справочниками

Отдельный драйвер помещает копию плагина в `<work>/.plugin` и передаёт этот
путь в `--plugin-dir`. `--restricted` сохранён. Фикстура, prompt и скиллы
те же. Все три варианта используют одинаковую схему расположения.

По три `gateway` на вариант, перемешанные seed 1, `j=3`; затем две клиентские
split-пробы. Предел — 50 ходов вместо 40 у штатного `abrun`; достигнутый
максимум — 31. Из-за изменения протокола сравнивать следует варианты внутри
этой серии, не объединяя их с первой.

| Среднее число ходов | 18.7 | 17.0 | 15.0 |

Средние цены ниже на 16% и 21%, но медианы выше на 20% и 13% соответственно.
Знак зависит от одной baseline-сессии за $0.5073: она сделала 31 ход и написала
тесты, которые затем прошли в harness. Эта сессия не исключена из расчёта.
При n=3 нельзя объявлять ни устойчивую экономию, ни статистически
подтверждённое ухудшение.

В первой серии `go-linting` загружен в 0/5 baseline, 1/5 split и 3/5 inline.
В повторе — 1/3, 2/3 и 1/3. Меняется объём остальных загрузок и работы,
а не только размер `go-http`. Один `go-linting` содержит 1654 слова — больше
всего сокращения здесь. Причинную роль нового заголовка Validation отдельно
не проверяли.

Провал inline на nil воспроизведён: сессия загрузила `go-defensive`, выполнила
`sorted := slices.Clone(accounts)` и вернула `null`. Это существующая ловушка
старой базы; загрузка owner-а сама по себе её не предотвращает.

## Клиентские проверки

Задача: написать переиспользуемый клиент GET `/status` с контекстом,
ограничением времени, отклонением non-2xx и лимитом ответа 64 КиБ. Это задача
реализации с записью файла, не вопрос о выборе скиллов.

После исправления расположения **CLIENTS.md успешно прочитан до первой
правки в 2/2 пробах**. Следовательно, прежний отказ чтения был реальным
ограничением стенда. Маленькая выборка не доказывает надёжность маршрутизации
на других задачах.

Все пять клиентских реализаций собираются. Отдельный тест через публичный
API и loopback HTTP-сервер отправляет валидный JSON с хвостом пробелов,
всего 65 553 байта. Реализации, использующие только
`json.NewDecoder(io.LimitReader(...)).Decode(...)`, принимают этот ответ:
первый объект помещается в лимит, а оставшееся тело не проверяется.

- В первой серии тест прошёл у baseline и одной split-реализации, провалился
  у второй split-реализации.
- В повторе обе split-реализации прочитали справочник и обе провалили тест.

Тест выполнен с `-race`; его исходник и вывод сохранены. Это наблюдаемая ошибка
полученного кода. Отдельного повторного baseline-клиента во второй серии нет,
поэтому причинно приписывать ошибку выносу нельзя. Компиляция не была выдана
за полную проверку клиентского контракта.

## Решение и проверка артефактов

Не переносить ни один вариант в основной скилл как подтверждённое улучшение
эффективности. Сокращение файла достигнуто, стабильный выигрыш сессии — нет.
Перед дальнейшими экспериментами со справочниками следует обеспечить их
читаемость в стенде. Повтор здесь выполнен отдельным драйвером; его код
сохранён в JSON.

- Для inline полный `go test -count=1 ./...` из `evals` прошёл.
- Для split пример декодирования и `quick_validate.py` прошли. Полный набор
  упал только на счётчиках справочников: новый файл требует 67 → 68 в двух
  манифестах и README на двух языках. Экспериментальная копия сохранила
  метаданные исходного плагина; split-patch не является релизным изменением.
- Пример декодирования в обоих вариантах совпадает с исходным. Проверены
  применимость patch, локальные ссылки и hashes исходников/журналов.
- Дополнительный gateway-тест взят из прежнего
  [артефакта](2026-09-08-go-implement-single-comparison-sonnet-5.sources.json).
  Он проверяет HEAD на трёх путях и nil/пустой список, но не полностью
  отфильтрованный непустой список. Golden и дополнительные тесты добавлялись
  после окончания модельных сессий.

Claude Code 2.1.263, Go 1.27.1, `claude-sonnet-5`, effort не задан.
В assistant-сообщениях всех сессий проверено имя модели. Цена включает
сопутствующий Haiku из `modelUsage`. Модели имели только
`Skill,Read,Glob,Grep,Edit,Write`; команды проверки выполнял внешний драйвер.

Всего **29 модельных сессий, $6.4621456**: первая серия $3.8052074,
повтор $2.6569382. Отказ чтения не был поводом удалить оплаченные сессии
из отчёта.

## Воспроизведение

Из `evals`, где `SPLIT_ROOT` и `INLINE_ROOT` — копии `74ca0fa` с соответствующим
patch:

```sh
go run ./cmd/abrun -corpus implement -tasks gateway -runner claude -model claude-sonnet-5 -arms baseline,reference -reference-root "$SPLIT_ROOT" -n 5 -j 2 -seed 1 -timeout 5m -keep -out /tmp/http-compact-gateway.json
go run ./cmd/abrun -corpus implement -tasks gateway -runner claude -model claude-sonnet-5 -arms reference -reference-root "$INLINE_ROOT" -n 5 -j 2 -seed 1 -timeout 5m -keep -out /tmp/http-compact-inline.json
```

Полный драйвер повтора `local_plugin_runs.py`, клиентские prompts, аргументы
CLI, проверки и collector находятся в поле `scripts` JSON. Перед запуском
на другой машине требуется заменить пути `base` и `tmp`. Для штатного
`abrun` stdout CLI сохранялся временной обёрткой с `tee`.
