# Написання нового Go-коду — 2026-09-08

У [go-code](../skills/go-code/SKILL.md#writing-new-code) додано окремий
розділ для нових функцій, пакетів і реалізації заглушок. Вхід залишається
`go-code`; додатковий скіл або модельний профіль не потрібен.

## Що змінилося

- Починати з потрібного API й реалізувати всі задані результати та помилки.
  Падіння acceptance-тестів на заглушках означає відсутню реалізацію;
  збереження такого panic не є метою рефакторингу.
- Обирати стан за часом життя та володінням даними. Спільні похідні дані
  обчислювати один раз; дублювати raw і derived state за конкретної потреби.
- Виділяти хелпери для спільної логіки або змістовної операції. `validate`,
  `toDomain`, `writeError` з прикладів не є переліком обов'язкових методів.
  Потрібні caller-ам інтерфейси й шари зберігаються.
- Перевіряти відповідність стандартного API конкретному контракту і спостережувану
  поведінку на публічній межі; компіляція без тестів її не доводить.

Це уточнює правила нового коду. Посилання на delete-first залишено для
рефакторингу; попередні staged-зміни й модельні звіти не переписували.

## Що показали наявні дані

Перераховано [наданий implement JSON GPT-5.6 Luna / Codex](evidence/2026-09-08-go-implement-control-gpt-5.6-luna-medium.json):
по 20/20 валідних сесій у кожному плечі. На `gateway` приріст рядків
90.8 без скілів проти 94.6 зі скілами, доданих функцій — 7 проти 15
за п'ять сесій. На інших трьох fixtures середній приріст рядків нижчий
зі скілами. Сирий звіт не містить production snapshots; кількість функцій
не встановлює, чи були вони зайвими.

Отже, проблема нового коду не зводиться до загальної заборони хелперів.
Поточна правка дає критерій їхнього змісту та меж застосування прикладів.
Гіпотеза про вплив прикладів на появу зайвих методів потребує окремого A/B;
причину попередніх результатів не встановлено.

[Повні знімки коду, інструкції, diff, відповіді та логи](evidence/2026-09-08-new-code-probes.json).

| Перевірка | До | Після |

| Незмінені golden-тести з `-race` | PASS | PASS |
| Physical production lines, включно з doc comments | 113 | 114 |
| Іменовані функції, без function literals | 1 | 1 |

Початкова заглушка падає на тому самому suite з `panic: not implemented`.
За одним прикладом виграшу в розмірі коду не встановлено; обидві реалізації
вже обходяться без додаткових іменованих хелперів.

Проби 48–49 пройшли за оцінкою основного агента. Валідатори скіла,
відносні посилання й `git diff --check` пройшли. Повний `go test` у `evals`
має два вже відомі падіння: ліміт довжини `PLAYBOOK` і застарілий golden опису
`go-code`; інші тести пройшли. Опис скіла не змінювали. Після структурної
перевірки відновлено посилання delete-first у гілці рефакторингу;
текст нового розділу відповідає перевіреному знімку.

Агенти окремо повідомили про недоступний lint через Go 1.26 у вибраному
ними binary. Golden PASS не означає lint PASS; перевірки розрізнено в evidence.

Для `gateway` проведено по одній незалежній реалізації з попереднім і новим
`go-code` в поточній GPT-6 Astra / Codex-сесії. Однакові завдання та вихідні
заглушки, окремі знімки скілів і каталоги; агенти не бачать golden-тестів
або чужого коду. Основний агент запускає незмінений golden suite на копіях
production-коду без тестів, створених моделлю. Знімки коду, різниці й логи
збережено; це не запуск `abrun` і не вимірювання ефекту на GPT-5.6 Luna.
